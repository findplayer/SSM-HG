# 七类逐类 F1、per-class 阈值与 GCN 基线（2026-09-20，§37 微调正典口径）

> **定位**：本文件回答两个问题——**(a) 7 种漏洞各自的 F1 是多少**（并在三个工作点上并列）；
> **(b) 关系盲 GCN 基线相对关系感知 RGCN 差多少**。两项**都零重训**。
> **权威数字出处**：主评估 `runs/*/seed*/results.json`；per-class 阈值 `eval_results/calibration{,_aug}/`；
> 程序汇总 `eval_results/per_class_f1.json`（由 `scripts/collect_per_class_f1.py --check` 生成，
> 会与 `calibrate.py` **逐位对拍**，不一致即拒绝落盘）。
> **口径**：§37 起正典 = **微调 CodeBERT**，`graph_dir = products/<语料>/graphs_ft/ss{S}`（含划分种子）。

---

## 0. 必读的三条限制（先看这个，再看表）

1. 🔴 **主库 ① 的逐类 support 低到 1**（`dos`/`front_running` 三种子各 1 个 test 正样本）。
   在这种支撑下，**单类 F1 一次判对判错就能跳 ±0.3–0.67**，逐类 F1 的**方差远大于任何跨配置差异**。
   表里把 support 打在同一行就是为了这件事——**逐类比较不可读，只有 micro/macro/合约级可读，且那三者也要看 std**。
2. 🔴 **per-class 阈值是高过拟合口径**：它逐类在 **val** 上选阈值，而 val 上 `dos`/`front_running`/`time_manipulation`
   各只有 **1 个正样本**。在 1 个正样本上"调 F1 最优阈值"在数学上近乎无约束（总能取到 F1=1）。
   §3 给出量化审计。**本口径不进主结果**（`decisions.md` §13）。
3. 🔴 **n=3 描述性**：本仓规范（`decisions.md` §26.7/§27.5）——**凡下「A 优于 B」的结论必须同配对 ≥9 点**，
   3 种子只用于报 mean±std。**本文所有跨配置比较都不构成方向性结论**，只作为"下一步该测什么"的线索。

## 4. GCN 基线（关系盲）——一个**必须诚实报告的负面结果**

### 4.1 设定与必须披露的两个混杂

- **唯一变量**：`--conv rgcn → gcn`。其余参数逐字取自正典 `config.json`（逐种子 `graph_dir` = `graphs_ft/ss{S}`）。
- 🔴 **混杂 1：GCN 是"关系盲"，不是"另一个数据集上的 GCN"**。`model.py` 的 `GCNConv` **完全忽略 `edge_type`**，
  即把 5 种语义关系塌成一张同构图。论文表格里必须写明这一点，否则会被读成"另一种 GNN 实现"。
- 🔴 **混杂 2：参数量不等**。RGCN `rgcn_params` = **205,754**（basis 分解）；GCN = **41,864**；合计
  **415,226 vs 251,336（−39.5%）**。⇒ 两者的差异**不能只归因于"有没有关系感知"**，
  也混着"少了 4/5 的关系参数"。要分离它需另做参数量匹配的对照（见 §5）。

### 4.2 结果：**在 ① 上两条臂分不开**

| 指标 | RGCN 正典 | GCN 基线 | 差异 |
|---|---|---|---|
| micro @0.5 | **0.7110±0.0389** | 0.5882±0.1060 | −0.1228 |
| **micro @val_thr** | 0.7297±0.0675 | **0.7759±0.0251** | **+0.0462（GCN 更高）** |
| macro @0.5 | **0.6091±0.0751** | 0.4309±0.0809 | −0.1782 |

### 4.3 怎么读这张表（**不要**读成"GCN 更好"，也**不要**读成"关系感知更重要"）

1. **GCN 在 `micro@val_thr` 上名义更高（+0.0462），但它在 `@0.5` 上崩得更厉害（−0.1228）**，
   且它的 `micro@0.5` std 是 **±0.1060**（正典 ±0.0389）——**区间完全重叠，n=3 判不了方向**。
2. **GCN 的"高 micro"是用误报换来的**：它的**合约级 F1 低 0.0818**（0.8601 vs 0.9419），
   即它在干净合约上误报更多。这与 §9 的 L1/L3 落差是同一个现象：**标签对级 F1 会奖励"多报"**。
3. **mAP 只差 0.0152，而 GCN 的 mAP std 是正典的 8 倍**（±0.0462 vs ±0.0056）⇒ 排序能力上两条臂**分不开**。
4. **GCN 的两类 AP 反而更高**（`front_running` 0.833 vs 0.611、oracle 0.889 vs 0.722）——
   几乎完全可分的类反而被关系盲模型排得更好，这与"关系感知带来收益"的预期**相反**。
5. **② 上正典逐类全胜**（micro 0.9913 vs 0.9802、合约级 0.9967 vs 0.9911），
   但 ② 在 0.99 的天花板上，差异意义有限。

### 4.4 这条结果与全仓其它证据**一致**，不矛盾

它和 §3.2 的消融发现是同向的：**21 个结构/特征开关里，没有一个给出能超过种子间波动的效应**
（`decisions.md` §38；除编码器微调外）。**唯一稳定有效的一维是输入表征质量**（§36 的 n=9：test micro +0.2466，t=+11.92）。
GCN 基线**强化**了这一点：把关系结构整个拿掉，排序能力（mAP）几乎不变（0.758 → 0.743，且在噪声内），
而把编码器从微调换回冻结，mAP 直接掉到 **0.3186**。

> **论文写法建议**：不要写"我们的 RGCN 优于 GCN 基线"。可写的、且被数据支持的是：
> **「在本文语料与骨架下，关系感知相对关系盲的增益不显著（n=3 分不开）；对结果起决定作用的是输入表征质量」**——
> 这本身是一个有价值的诚实发现，但**它是一个"方法贡献被削弱"的结论，须由作者裁定是否接受**。
> 若要主张 RGCN 的优势，**必须先做**：参数量匹配的 GCN（§4.1 混杂 2）+ **n≥9 同配对**（§0 限制 3）。

## 6. 复现命令（全部零重训，除训练 GCN 那 6 个 run）

```bash
cd /home/saumarez/projects/deep-learning/SSM-HG

# ---- (1) per-class 阈值（零重训，读 test_probs.pt / val_best_probs.pt 缓存）----
python scripts/calibrate.py --runs-dir runs             --out-dir eval_results/calibration
python scripts/calibrate.py --runs-dir runs/augmentation --split-dir products/augmentation/splits \
                            --out-dir eval_results/calibration_aug

# ---- (2) 七类逐类 F1 汇总（纯聚合；--check 与 calibrate.py 逐位对拍，不一致即拒绝落盘）----
python scripts/collect_per_class_f1.py --check
#   → eval_results/per_class_f1.json

# ---- (3) GCN 基线（唯一有训练成本的一步：6 run ≈ 2 分钟 GPU）----
for s in 0 1 2; do
  python scripts/train.py    --seed $s --split-seed $s --conv gcn \
      --graph-dir products/alldata/graphs_ft/ss$s --out-dir runs/baseline_gcn
  python scripts/evaluate.py --seed $s --runs-dir runs/baseline_gcn \
      --graph-dir products/alldata/graphs_ft/ss$s --split-dir products/alldata/splits
done
python scripts/evaluate.py --summarize --runs-dir runs/baseline_gcn
# ② 同理，另加：--split-dir products/augmentation/splits \
#   --label-file products/augmentation/contract_labels_repaired.json --label-key-mode stem
#   --out-dir runs/baseline_gcn_aug

# ---- (4) GCN 的诊断/概率缓存（逐 seed 传**匹配的**编码器树！见下）----
for s in 0 1 2; do
  python scripts/diagnose.py --runs-dir runs/baseline_gcn --seed $s \
      --graph-dir products/alldata/graphs_ft/ss$s --split-dir products/alldata/splits
done
python scripts/diagnose.py --runs-dir runs/baseline_gcn \
    --graph-dir products/alldata/graphs_ft/ss0 --split-dir products/alldata/splits   # 聚合
```

> 🔴 **第 (4) 步的坑**：`diagnose.py` 只有**一个** `--graph-dir`，但正典的编码器树是**逐划分种子**的
> （`ss{S}` 必须配 `--split-seed S`）。**首次**跑（无 `test_probs.pt` 缓存）会真的去加载图，
> 此时传错 `ss` 会拿 A 树的特征喂 B 树训出来的模型 ⇒ **数值错但不报错**。
> 故必须**逐 seed 传匹配的树**，最后再跑一次不带 `--seed` 的聚合（此时全部命中缓存，`graph_dir` 不再影响数值）。
