### 4.1 ✅ 已裁定并执行 #1：`micro_f1` 的实现口径（2026-09-17；**结论见 `decisions.md` §28**）

> ✅ **用户已裁定执行方案 B**（修指标 + 全量重训），并于 2026-09-17 完成。

> **以下为裁定前的原始问题陈述，保留作记录。**

**现象**：`scripts/metrics.py::micro_f1` 把两个输入都做了 `.ravel()`：

```python
f1_score(_as_numpy(y).ravel(), _as_numpy(p).ravel(), average="micro", zero_division=0)
```

一维 `{0,1}` 数组被 sklearn 判为 **binary**，`average="micro"` 于是在**两个类别上**平均 →
micro-P = micro-R = micro-F1 = (TN+TP)/N = **准确率**。而 docstring 写的是「**标签对级** micro-F1」。

**根因：sklearn 按输入数组的「形状」分派任务类型**，`.ravel()` 把 `[N,7]` 的 multilabel-indicator 变成一维 binary：

| 检验 | 二维（多标签） | 一维 `.ravel()`（本仓实现） | 准确率 |
|---|---|---|---|

### 7.1 为什么不能「先定最优设计、再修指标」：顺序问题

## 9. 误报率与漏报率（2026-09-17 新增）

> **为什么加**：第 0–8 节用的 micro-F1 / macro-F1 / mAP 都是**分数**，回答的是"方法好不好"；
> 它们**不回答**"这个工具敢不敢上"。误报率（FPR）与漏报率（FNR）才是运维口径。
> **来源**：`runs/**/seed*/test_probs.pt` 缓存（已入库）→ `python scripts/error_rates.py` → `runs/error_rates.json`。
> **零重训、零 GPU**；纯函数与恒等式已由 `tests/test_error_rates.py`（9 例）锁住。
> ⚠ **本节不进主结果口径**，不改变 §1–§8 的任何数字；新增的是**读法**。

### 9.1 多标签下「误报率」有三个互不相等的定义（必须先说清）

| 层 | 问的是 | 定义 | 主库① @val_thr（**新正典**） |
|---|---|---|---|
| **L1 标签对级** | 全部 `(合约, 类别)` 判定里错了多少 | `FPR=ΣFP/(ΣFP+ΣTN)`、`FNR=ΣFN/(ΣFN+ΣTP)` | FPR **2.5%** / FNR **22.2%** |
| **L2 逐类** | 某一类判错了多少 | `FPR_c=FP_c/(FP_c+TN_c)`、`FNR_c=FN_c/(FN_c+TP_c)` | 见 §9.4 |
| **L3 合约级** | 一个合约整体判错了多少 | 无漏洞却报出≥1类 / 有漏洞却一类没报出 | FPR **2.62%** / FNR **8.02%** |

> ⚠ **本表已按 2026-09-20 新正典刷新**（微调 CodeBERT）。旧载 L1 `5.1% / 49.2%`、L3 `18.3% / 30.6%` 为冻结口径，作废。
>

> **误报侧两者基本相等（2.5% vs 2.6%）**，**漏报侧相差 2.8 倍且 L1 更高（22.2% vs 8.0%）**。
> 机制解释（对任意工作点成立的那部分）：L1 的分母是**标签对**，`dos`/`time_manipulation` 这类
> support=1 的稀有类一漏就是该类的整条召回，故 L1 的 FNR 被稀有类抬高；

**二分类占了便宜的地方（要诚实承认）**

**数据采集 / 标注成本：这个维度是"平局"，不构成任何一方的优势**

> ⚠ **原稿此处写错了重点**（2026-09-17 修订）：原写"改二分类不会省标注成本"，读起来像二分类在数据侧吃亏。
> **准确的说法是两边都是零成本**——二分类标签**同样是现成的**，不需要任何新标注。

- **两侧都现成，一行代码之差**：
  - 七类：`alldata(readonly)/contract_labels.json` 的 `targets` 是**已有 7 维向量**（2002 条）；
    `MVD-HG-dataset/{类}_contract/contract_labels.json` 里每类是一个**标量 0/1**（如 reentrancy 543 条）。
  - 二分类：`any(targets)` —— **一行派生，零标注**。
  → **"标注/采集成本"这一维对两边都是 0，因此它既不是二分类的优势，也不是它的劣势。** 原稿的框架错了。
- **二分类在数据侧的真实优势只有一条**：把 7 个稀有类的正样本**合并**，正样本率从
  `127/(453×7) = 4.0%` 抬到 `127/453 = 28.0%`，把"每类 test 只有 1–2 个正样本"的 oracle 上限问题（§1.1）
  **直接消掉**。这是实质优势，**且本仓已免费拿到**（就是 L3 层，§9.2）——不需要改任务。
- **外部语料反向**：DIVE 有 **68.2%** 是多标签（`report_data.md` §2.3.1）。改二分类会把这部分的类别信息
  在**跨语料评测**（阶段 G）上整块作废——而 DIVE 正是补稀有类 support 的那条路。

**结论：不改主任务为二分类，改为「主表七类 + 并列 L3 合约级」双报。**

1. **研究点锁死七类**（大纲），改二分类等于放弃研究点；且 §1.1 已证明低指标是 **support 事实**，
   改问法只是**回避**它、不是解决它（换问法不产生新信息——L3 由同一批权重派生，§9.2）。
2. **七类的不可替代价值在"可操作性"与"可解释性"**：告警必须给出**修哪儿**——
   `reentrancy` 改 CEI、`access_control` 加 modifier、`uncheck` 补返回值检查，处置动作完全不同；
   二分类只给"有问题"，人工二次分类的成本正是七类头省下的。M1 的节点可疑度 $a_v$（解释信号）
   也只有在类别语义下才落得下去（"哪些节点对应哪类漏洞"）。
3. **架构上七类头已经"免费包含"二分类**：`any()` 一塌就是二分类；**反向不成立**。
   7 头共享主干还让稀有类能借用高频类的信号（`reentrancy`/`uncheck` 同依赖外部调用模式）——
   拆成 7 个独立二分类器反而更差。
4. **写法建议**：主表报七类（研究点要求的粒度）+ **并列 L3 的 FPR/FNR 列**（回答"敢不敢上"），
   并在论文里明说 **L1（标签对级）与 L3（合约级）落差的原因**（§9.1）。
   🔴 **已按新正典改写**：落差**不在误报侧**（新正典下 L1 FPR 2.55% vs L3 2.62%，**≈1.0 倍**），
   而在**漏报侧**——L1 FNR **22.2%** vs L3 **8.0%**，**L1 比 L3 高 2.8 倍**。
   （旧载"L1 与 L3 差 3.6 倍、且方向相反"为冻结编码器口径，已作废。）
5. ✅ **原记为候选的"阈值目标"线索已实测，见 §9.6.2**：把阈值搜索目标换成合约级二分类 F1，
   确实让**它自己那个指标**在 test 上 **+0.0023**（⚠ n=3，描述性；= 已按新正典重算，旧载 +0.036），
   但代价是 micro-F1 **−0.1221**（旧载 −0.092）；
   **且它作为选择判据更不稳**（平台宽 1.7 倍、2.8% 的 run 整条曲线不分高下）。
   → **结论：不换。** 🔴 且新正典下这笔交换**从"有得有失"变为"纯亏损"**（收益≈0 而代价翻倍），
   该候选**关闭**，不再作为待办。

  新实测：合约级只 **+0.0023**（≈0，且 seed0 上还**变差** 0.976→0.952），代价却是把 micro-F1 砍掉 **0.1221**，
  阈值整体大幅下调（0.75/0.60/0.80 → **0.20/0.45/0.35**，**用大量误报换一点点召回**）。
  → 旧的「+0.036 收益换 −0.092 代价」至少在两端都有数；新的**只有代价、没有收益**。
  ② 增强集上两个目标**逐种子几乎相同**（Δ合约级 +0.0000 / Δmicro −0.0022）。
- **但作为"选择判据"它更弱**（这是新证据）：在 **106 个 run** 上比较两条 val 曲线（13 格）——

| 判据 | 13 格中的不同取值 | 距最优 ≤0.01 的格点数 | 整条曲线都在平台内的 run 占比 |
|---|---|---|---|
| 现行 micro-F1 | **12.3** | **1.2** | 0.0% |
| 合约级二分类 F1 | 9.4 | 2.0 | **2.8%** |

  **二分类目标的最优更"平"**（平台宽 1.7 倍、分辨率低 24%、有 2.8% 的 run 整条曲线不分高下 ⇒ 阈值选择等于随机）。
  原因很直接：**val 只有 45 个合约**，而标签对级 micro-F1 在 `45×7 = 315` 个格子上算——
  负样本池大 12 倍，自然分辨得更细。**当选判据的样本单元更少时，"更接近部署口径"换不来"选择更可靠"。**
- **跨种子稳定性也印证**：二分类 argmax 在增强集上是 **0.70 / 0.35 / 0.65**（跨 7 格），
  而 micro-F1 是 0.80 / 0.80 / 0.65。前者几乎不可复现。

#### 9.6.3 早停：现行判据的分辨率**并不差**，换成二分类只会更粗

用 106 份 `log.txt` 实测现行早停判据（`val_micro_f1`，⚠ 注意它是**每 epoch 在 13 个阈值上取 max**，
即"每轮都做一次 oracle 阈值选择"，见 `train.py:469`）：

| 量 | 实测 |
|---|---|
| 平均 epoch 数 / 其中 `val_micro_f1` 的不同取值数 | 21.3 / **17.7**（分辨率高，非退化） |
| 最优值在多轮并列的 run 占比 | 32.1%（`>` 为严格比较 → **并列取最早 epoch**，偏保守，是良性行为） |
| 早停选中位置（占全程） | 71.6% |
| 末轮即最优的 run 占比 | 13.2%（末轮 vs 最优平均差 **0.0286** ⇒ **早停确实在做功**） |

**推论**：既然（a）现行判据分辨率 17.7/21.3 并不差，（b）换成合约级二分类会把判据的分辨单元从 315 降到 45
（§9.6.2 已实测其平台更宽），（c）该判据还被常量解刷到 0.62/0.93（§9.6.1）——
**三条同向，结论是：把早停/调度/选点改成合约级二分类判据，只会让训练控制流更差。**

#### 9.6.4 必须区分「判据」与「训练目标」（本节的边界）

⚠ **§9.6.1–9.6.3 证明的是"合约级二分类作为度量/选择判据更弱"，不是"训练一个二分类模型更弱"。**

- 上面所有证据针对的是 **F1 这类聚合分数**。真的**训一个单头二分类模型**时，梯度来自 **BCE 损失**而非 F1，
  损失对每个样本都有梯度（不像 F1 只看 `any()`），退化风险小得多。
- 而且二分类有一条**真实的数据侧优势**（§9.5）：正样本率 4.0% → 28.0%，7 个头共享主干时的
  极端不平衡与稀有类干扰会消失——**单头模型可能确实学得更好**。
- **本仓未测**。要测需真的训一个二分类臂（改 `model.py` 头数 + `dataset.py` 的标签聚合 + 一套评估），
  **不是零重跑项**，故本节只给"判据侧"的结论，不越界到"模型侧"。
- **一句话总结本节**：**"合约级二分类"应当作为报告口径（§9.2），不应当作为训练控制流口径。**

#### 9.6.5 ★ 判决实验结果（2026-09-17，`--head binary` 臂跑完）

> 🔴 **工作点警告（2026-09-20 补）**：本节 36 个 run（`runs/binary_arm/`）全部是**冻结编码器**产物，
> §37 未重跑（`decisions.md` §39.6 待办 3）。⇒ 本节的 Δ 与 t **不得与新正典的七类结果并列解读**，
> 结论「排序略强、判决无差异」**只在冻结工作点上成立**；数据卷 §3.5 已有同款标注，本节原缺。

**§9.6.4 留下的开口已补上**：真训一个单头二分类模型，`decisions.md` §31。
n=9 同配对（train_seed 3/4/5 × split_seed 0/1/2），**唯一变量 = 输出空间**
（同 seed 下 12/12 共享张量逐位相同，`tests/test_binary_arm.py` 机检）。
证据本体：`experiments/binary_{main,aug}_paired.json`（val）；test 由 `test_probs.pt` 同配对重算。

**① 主库（test 与 val 同配对 Δ，n=9；基线 = 七类臂塌成 `max_c p_c` 的同一口径）**

| 指标 | 工作点 | 七类塌缩 | 二分类臂 | Δ | t | 判定 |
|---|---|---|---|---|---|---|
| **AP**（阈值无关） | val | 0.9237 | **0.9572** | **+0.0335 ± 0.0335** | **+2.99** | ✅ **显著** |
| AP | test | 0.8564 | 0.8898 | +0.0334 ± 0.0848 | +1.18 | ⚠ 点估计相同、方差不支持 |
| F1 | @0.5 | 0.8207 / 0.8017 | 0.8188 / 0.7923 | −0.0019 / −0.0094 | −0.07 / −0.42 | ❌ 无差异 |
| F1 | @val_thr | 0.8028 / 0.7353 | 0.8264 / 0.7807 | +0.0236 / +0.0453 | +0.74 / +1.42 | ❌ 不显著 |

**② 增强集**（val 与 test 同配对；该语料近天花板 → 数值空间本就极小）

| 指标 | 七类塌缩 | 二分类臂 | Δ（val / test） | t（val / test） |
|---|---|---|---|---|
| AP | 0.9980 / 0.9992 | **1.0000 / 0.9999** | +0.0020 / +0.0007 | **+3.09 ★ / +4.71 ★** |

| FNR @val_thr | 0.0231 | **0.0043** | −0.0188 | **−3.70 ★** |

> ⚠ **② 的显著性要打折读**：它建立在 `AP 0.998 → 1.000` 这种"离满分只剩 0.002"的空间上。
> 显著的是"几乎完美的模型更接近完美"，**不是**"二分类在困难语料上更强"。② 的判定意义有限
> （§9.6.4 已预告这是天花板语料）。

**三条读数**

1. ✅ **回答原问题：二分类模型确实略强，但只强在"排序"这一环。**
   AP（阈值无关）在**两组语料、val 与 test 的四个点估计上全部同向为正**（+0.033 / +0.033 / +0.002 / +0.001）。
   而**阈值化的 F1 在主库上没有任何工作点出现差异**（t = −0.07 / −0.42 / +0.74 / +1.42）。
   → 结论：**专用二分类头改善的是排序质量，不是判决质量。**
2. ⚠ **主库的 AP 优势在 test 上不足以判定**：val 上 t=+2.99（过线），test 上 t=+1.18（不过线），
   而**点估计几乎相同（+0.0335 vs +0.0334）**——差别全在方差（test 侧 std 是 2.5 倍）。
   这是"效应量一致、但 test 更噪"的典型形态，不是"效应消失"。
3. 🔴 **不足以支持"把主任务改成二分类"**（与 §9.5 的结论一致，现在有了实证）：
   ① 上部署相关的 F1 **零增益**，FNR 的 −0.0971（少漏 9.7 个点的漏洞合约）虽不显著但方向可观、
   代价是 FPR +0.0357（多误报 3.6 个点的干净合约）——**这是 FPR 与 FNR 之间的交换**，
   ⚠ 与 §9.2 读数 3 所述的现行现象（@0.5→@val_thr 误报降、漏报升）**方向相反**，不要混为一谈；
   不是能力提升。而二分类臂**放弃了全部类别信息**（§9.5 的可操作性论证）。

> **与 §9.6.1–9.6.3 的关系**：那三节证明的是**"合约级二分类作为判据"更弱**（常量解刷分、平台更宽），
> 本节证明的是**"专门为二分类训练的模型"在排序上略强**。**两者不矛盾、不可互相引用**——
> 前者否定的是"拿它当早停/阈值目标"，后者肯定的是"单头模型本身有点用"。
> 因此 §9.6 的裁定（**判据不改**）与本节结论（**模型略优但不换主任务**）同时成立。
