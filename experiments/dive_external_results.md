## 1. 做了什么

1. **消融全部重跑**（正典改为微调 CodeBERT，`decisions.md` §37）：① 21 臂 × 3 种子、② 21 臂 × 3 种子 = **126 run，0 失败**。② 由原设计 5 臂扩到 21 臂，与 ① **逐臂对齐**。
2. **DIVE 外部测试**：把训练好的模型**原样**搬到 DIVE 抽样集上推理。协议**不重抽**——沿用已冻结的 `seed=0 / n=900`；DIVE 实测解析后 **890 图**。
3. **三方并列表**：① 内测 / ② 内测 / DIVE(①模型) / DIVE(②模型)。

**三条纪律**（`AGENTS.md` + 大纲 5.1）：

- DIVE **只读**，且**不参与任何模型选择**（训练/验证/早停/阈值/架构都不看 DIVE）；
- 外部测试的阈值**只读源语料验证集**的搜索结果（`thresholds.json`），**绝不在 DIVE 上重搜**；
- 编码器矩阵：每个语料的模型配**它自己**微调的编码器。图结构只建一份，特征建三套。

## 3. ①② 内测的消融分析（通俗版）

### 3.1 一眼看去"变好"的项，多半是噪声

① 上有 11 项 Δ 为正（`numbases4` +0.078、`numbases3` +0.050、`layers1` +0.046…）。
**但这些都不能当作"该组件有害"的证据**，原因有三：

1. **正典的种子间 std 是 ±0.0675** —— 比绝大多数 Δ 都大；
2. **n=3 判不了 ±0.05 量级的效应**（`decisions.md` §26.7/§27.5 的两条硬规矩，本仓已为此栽过两次）；
3. 而**主实验本身就不是逐位可复现的**：同一配置重跑，Δmicro@0.5 实测 0.0000 / 0.0135 / 0.0223（重跑抖动 ≈0.012，约为种子间 std 的 40%，`decisions.md` §36.4，根因是 CUDA 归约顺序非确定性）。

★ 号只标"|Δ| 超过正典的种子间 std"，意思是**值得复核**，**不是**"效应已确认"。

### 3.2 唯一一个大到不用统计就能看见的：`cb_frozen`

| | ① | ② |
| --- | --- | --- |
| Δmicro@val_thr | **−0.276** | **−0.041** |
| Δmicro@0.5 | −0.298 | −0.057 |

**通俗说**：把编码器从"微调过"换成"原装 CodeBERT"，模型性能掉掉掉——① 上掉了近 28 个点，② 上掉 4 个点。
这与 n=9 同配对复核（`decisions.md` §36）一致：test 侧 8/8 指标显著，`micro@0.5` +0.2466（t=+11.92），9/9 配对全为正。
**这是本论文最结实的一条消融结论**：瓶颈在**输入表征质量**，不在图结构。

### 3.3 `cb_unlimited`：Δ 恰为 0，但**不能**读作"这个组件没用"

`cb_unlimited` 在 ① 上六个指标与正典**逐位相同**。我逐层查到根（`decisions.md` §38.4）：

| 检查 | 结果 |
| --- | --- |
| 变体的 `_pyg.pt` | 20/590 图边集确实不同（且只增不删） |
| 其中在训练池内的 | **只有 9 张**（11 张是 `buggy_*`，已被剔除） |
| 两次训练的 `best.pt` md5 / epoch-0 loss | **都不同**（0.960**3248** vs 0.960**2375**）→ 确实重训了 |
| `test_probs.pt` 的差异 | maxΔ 0.012–0.051 → 概率确实动了 |
| **预测矩阵翻转数** | **0 / 322** → 差异全落在阈值带内，一个决策都没推动 |

**通俗说**：这个消融确实改了图、也确实重训了模型，但改动太"轻"（① 只有 9/453 张图受影响），
而 ① 的测试集只有 46 个合约、322 个标签对，这点扰动推不动任何一个判断。
② 侧同理（199/1774 图改动，但 ② 已在天花板 0.9901，`Δmicro@0.5 = 0.0000`）。

⇒ 论文里这一项必须写成「**本实验未能检验该问题（无功效）**」，
**不得**写成"CALLBACK_RISK 上限不重要"。它本就还叠加着"稀释"缺陷（① 干预面仅 3.4%）。

### 3.4 ② 为什么看不出任何东西

② 上**除 `cb_frozen`（−0.041）外，其余 20 项 Δ 全部落在 ±0.012 内**（实测范围 −0.0114 ~ +0.0011）。
**通俗说**：② 的 micro-F1 已经是 0.99，天花板效应——**没有上升空间，也没有下降空间**。
所以 ② 这一组的作用是"证明模型在训练信号充足时能到顶"，
**不能**用来论证"某个组件重要或不重要"；唯一例外仍是编码器（§3.2）。

### 3.5 一个被反复观察到的形态：拿掉组件，排序变好、F1 变差

① 上 ΔmAP 与 Δmicro 常常反号（`ablation_results.md` §6 有完整计数与复算口径）。
**通俗说**：去掉某个输入后，模型更"敢"给稀有的正类打高分（排序指标 mAP 上去），
但整体阈值化的 F1 反而下来。这不是自相矛盾，是**用召回换排序**。
⚠ 这个计数在文档里**已写错过两次**（原文如此），引用前必须按 `ablation_results.md` §6 的口径复算。

## 4. DIVE 外部测试分析（重点）

### 4.1 F1 为什么会崩成这样

| | ① 内测 | DIVE（①模型） |
| --- | --- | --- |
| 正典 micro-F1@val_thr | 0.7805 | **0.0065** |
| 正典 micro-F1@0.5 | 0.7391 | **0.0156** |
| 正典 mAP | 0.7531 | 0.3927 |

> （上表为**最佳种子**口径 ① seed2；mean±std 口径下 DIVE 为 0.0152 / 0.0282，结论相同。）
>
> 🔴 **本表整代是 5 轮档**（内测列与 DIVE 列都是）。换代后的 ① 正典 DIVE 读数见 **§0.1**
> （micro@val_thr **0.0034**、micro@0.5 **0.0040**、mAP **0.3921**，均为 3 种子 mean）
> —— 方向与本节结论一致（仍是"近乎归零"），但**绝对值更低**。

一眼看是"模型完全废了"。但**这不是故障**（§4.2），而是**类别先验错配**：

### 表 4：DIVE 类别先验 vs 训练语料（① 模型）

| 类 | 训练语料正样本率 | DIVE 正样本率 | 漂移 |
| --- | --- | --- | --- |
| access_control | 0.030 | **0.758** | **+0.728（25 倍）** |
| reentrancy | 0.058 | 0.525 | +0.467（9 倍） |
| arithmetic | 0.028 | 0.421 | +0.394（15 倍） |
| time_manipulation | 0.006 | 0.260 | +0.254（43 倍） |
| uncheck | 0.097 | 0.274 | +0.178 |
| dos | 0.011 | 0.152 | +0.141 |
| front_running | 0.006 | 0.034 | +0.028 |

**通俗说**：模型是在一个"**几乎什么都没有**"的世界里长大的——① 的池子里 453 个合约有 **326 个是七类全零**（正常合约），
所以它学到的是"先默认没有问题"。把它扔到 DIVE——那里 **76% 的合约都有访问控制问题**——它还是按老习惯几乎什么都不报。

实测证据：

- 模型输出的概率**中位数只有 0.097**，而 DIVE 的真实正样本率是 **34.6%**；
- 在 @0.5 下它只判出 **0.95%** 的标签对为正；把阈值压到 0.1 才判出 **49.7%**（真值 34.6%）——**概率里是有信号的，只是整体被压低了**；
- 旁证：DIVE 的 **103 个正常合约**上，① 模型的合约级误报率只有 **0.65%**（@0.5 为 2.6%）——极度保守，正是上面这个成因的直接后果。

### 4.2 先排除"是不是我的处理管线坏了"

已逐条排查，都不是：

| 疑点 | 检查结果 |
| --- | --- |
| 图表加载对不对 | 7 棵树 + 12 棵变体树全部通过 `verify_channels="all"`（含逐通道 sha256 校验） |
| 标签有没有对错 | 修掉 `stem_key_of` 的 bug 后 **890/890** 全部匹配；逐类 support 与抽样清单一致 |
| 是不是模型输出死掉了 | 不是：概率有梯度（p50 0.097、p99 0.50、max 0.86），按类别看 AP 有高有低 |
| 是不是事件本身太难 | 不是：同一批图，`time_manipulation` / `uncheck` 两类**明显高于随机**（见 §4.3） |
| 是不是我改了阈值 | 没有：阈值逐字取自源语料 `thresholds.json`，**DIVE 上从未重搜** |

⇒ **是真实的跨数据集泛化现象**，不是管线故障。

### 4.3 🔴 最重要的发现：把 mAP 减去"随机基线"之后

**关键前提**：一个**完全随机**的排序器，它的期望 AP **恰好等于该类的正样本率**。
所以 DIVE 上"mAP = 0.40"听起来还行，其实**大部分是白送的**——因为 DIVE 的正样本率本来就高。

### 表 3b：逐类 AP 与随机基线的对照（阈值无关）

**① 模型 → DIVE**

| 类 | DIVE 正样本率（=随机 AP） | 逐类 AP | **AP − 随机** | 判定 |
| --- | --- | --- | --- | --- |
| access_control | 0.758 | 0.776 | +0.018 | ≈ 与随机不可分 |
| arithmetic | 0.421 | 0.400 | **−0.022** | ❌ 低于随机 |
| dos | 0.152 | 0.205 | +0.053 | ✅ 有信息 |
| front_running | 0.034 | 0.065 | +0.031 | ≈ |
| reentrancy | 0.525 | 0.594 | +0.070 | ✅ 有信息 |
| time_manipulation | 0.260 | 0.381 | **+0.122** | ✅ 有信息 |
| uncheck | 0.274 | 0.328 | +0.054 | ✅ 有信息 |
| **mAP** | **0.346** | **0.393** | **+0.047** | |

> ⚠ **逐类数字随种子波动很大**（这正是保留 mean±std 附录的理由）：
> `access_control` 在 mean±std 口径下是 **−0.010（低于随机）**，在最佳种子下变成 **+0.018**；
> `dos` 从 +0.023 变成 +0.053。**跨种子稳定为"明显有信息"的只有 `time_manipulation` 与 `uncheck`。**

**对照：同一模型在 ① 自己的测试集上**（同一脚本 `--selfcheck` 复算，与 `evaluate.py` 既有产物**逐位相同**）

| | mAP | 随机基线 | **AP − 随机** |
| --- | --- | --- | --- |
| ① 同分布内测（seed2） | **0.7531** | 0.0652 | **+0.6878** |
| ① 模型 → DIVE（seed2） | 0.3927 | 0.3462 | **+0.0465** |
| ② 模型 → DIVE（seed1） | 0.3630 | 0.3462 | **+0.0168** |

**通俗说**：

- 在自己家里，模型比瞎猜强 **0.688**；
- 换到 DIVE，只比瞎猜强 **0.047** —— **只保住了 6.8%**（② 模型更低，仅 +0.017）。

> ✅ **换口径不改结论**：改为最佳种子后保住比例从 7.4% 变成 6.8%，**结论方向完全不变**。
> 这说明"排序能力跨数据集大幅退化"是**数据事实**，不是挑种子挑出来的。

**这一条推翻了"排序能力迁移住了、只是阈值失配"的直觉判断。**
只看 mAP 的绝对值（0.40 vs 0.30）会以为"跨数据集排序还行"；
**只有减去随机基线才看得出排序本身也大幅退化**。
如果论文只报 F1，会以为问题全在阈值；只报 mAP，会以为问题不大。**两者都报、并且减去基线，才看得见真相。**

### 4.4 消融结论能不能外推到 DIVE？——不能

看表 2 的 ΔDIVE 两列：

- **① 模型的 21 个臂在 DIVE 上全部落在 0.0037 ~ 0.0326 这个区间**（最佳种子口径，见
  `comparison.md` 表 1′.micro@0.5 第一列）——**都处在"近乎全判负"的退化区，什么都分不出来**；
- **② 模型**有 `layers3` +0.139、`cb_rev` +0.067、`dfg_dep` +0.052 三个 `★`，
  但它们的 std 分别高达 ±0.116 / ±0.162 / ±0.040 —— 且 ② 在 DIVE 上的绝对水平只有 0.06，
  **这些"提升"是在一个近乎失效的工作点上测的，不具备可用性含义**。

⇒ **结论：本实验的消融排序不能外推到 DIVE。** 这不是方法的失败，而是**先验错配把整个工作点压垮了**，
导致所有臂都落进"几乎全判负"的退化区，彼此无从区分。

## 6. 局限与披露（写论文时必须带上）

1. **DIVE 只抽样 900（实测 890）**，非全量 21696。协议是 `seed=0` 的**一次确定事件**，
   逐类 support 见 §7；`front_running` 仅 30 个正样本。
2. **每类 support 不均**：`dos` 135、`front_running` 30，逐类读数必须与 support 同看。
3. **①② 的 Δ 是 n=3 描述性**：判"干预有效/无效"须另做同配对 ≥9 点。
4. **主实验非逐位可复现**（CUDA 归约顺序），重跑抖动 ≈0.012，约为种子间 std 的 40%。
