# 混淆计数审计：micro-F1 / macro-F1 背后的 TP / FP / FN

> 程序生成（`scripts/audit_confusion_counts.py`）。**指标不在此重实现**：F1 一律走 `metrics.micro_f1` / `metrics.macro_f1`，本脚本只**数计数**。
>
> 🔴 **计数单位 = `(合约, 类)` 标签对**，不是合约。7 类 × N 个测试合约 = 7N 个标签对。故 `TP + FP + FN` 的量级在几千，而测试合约只有几十/上千个。
>
> ```
> micro-F1 = 2·TP / (2·TP + FP + FN)   ← 七类**池化**成一组计数（标签对级全局）
> macro-F1 = mean(逐类 F1 的 7 个值)     ← **先逐类**算 F1，再**等权**平均
> ```
>
> 🔴 **两个汇总列不共用一套计数**：micro 用池化后的一组；macro 用逐类各自的 TP/FP/FN先得 7 个 F1 再平均 ⇒ **macro 无法由池化计数反推**，必须逐类看。
>
> 🔴 **三种子的计数不可相加**（每种子是不同划分 + 不同模型）⇒ 下表**逐种子**列计数，**不列合计**。也因此**不能**用「计数均值」去算 micro —— 表里报的是**逐种子 F1 的 mean±std**，两者数学上不是一回事（Jensen 不等式）。
>
> 🔴 **传统工具行的分母更小**（只数 `status==ok` 的合约），逐行可比性见 `main_aug_f1_summary.md` §0.1。
