## 1. 主实验（阶段 E：MVD-HG 内部测试，3 种子）

### 1.1 实验设置

- **命令**（仓库根目录，`python scripts/…`）：
  ```bash
  # 正典（2026-09-19 起）：编码器先在训练标签上微调，图目录随之变为 graphs_ft/ss{S}
  python scripts/train.py --seed {0,1,2} --epochs 200 --batch-size 32
  python scripts/evaluate.py --seed {0,1,2}
  python scripts/evaluate.py --summarize
  ```
- **编码器（2026-09-19 起属正典的一部分，`decisions.md` §37）**：CodeBERT 由「冻结」改为**在训练标签上监督微调**
  （stage-1，先于 GNN，两段式）；正典 `graph_dir` 因此从 `products/alldata/graphs`（冻结）变为
  **`products/alldata/graphs_ft/ss{S}`**（微调，**含划分种子** ⇒ 每个开关臂的 `graph_dir` 必须逐种子取）。
  冻结版保留为**消融/对比臂 `cb_frozen`**（大纲 5.4.2 该项方向随之反转）。
  ⚠ 微调段消耗与超参见 §1.5 与 `canonical_ft_numbers.md` §D；⚠ **边界**：编码器是在**训练标签**上监督微调，论文须写明（§36）。
- **环境**：`cuda`（NVIDIA RTX 4070 Laptop）、torch 2.0.1+cu118、python 3.11.3、torch_num_threads 12（出处 `runs/seed*/config.json::environment`）。
- **超参**（主实验未传任何覆盖，均取默认，出处 `config.json::args`）：lr=1e-4、weight_decay=1e-4、batch_size=32、max epochs=200、prior_dropout=0.2、struct_dropout=0.2、model_dropout=0.3、lambda_var=1e-3、tau_var=0.1、num_bases=5、hid=128、conv=rgcn、scheduler_patience=3、early_stop_patience=5、drop_edge_prob=0.0、cb_channels=`cb_func,cb_node`、feat_groups=`all`。
- **模型维度**（出处 `config.json::derived`）：D_struct=30、fuser 融合输入维=1631、fuser 输出（=SSMHG 输入）维=128、num_relations=5、num_classes=7；参数量 fuser 209,472 + RGCN 205,754 = **415,226**。
- **语料口径（2026-09-14 起）**：590 图 → 剔 buggy_* 后 500 → 两级去重 → 池 **453**（正 127、全零 326、多标签 1）。较修订前的 581/495/448 多 5 个非 buggy 样本（`decisions.md` §18：delegatecall 过滤规则修订，恢复 2 个 access_control 正样本）。**旧 448 池的结果存档于 `runs/prior_448pool/`，不得与新数字跨口径混用。**
- **Dropout 语义（2026-09-16 修正）**：`--prior-dropout 0.2` / `--struct-dropout 0.2` 中的 `0.2` 是**丢弃率**——
  每个图以 20% 概率把该通道整幅置零（`0`=关闭、`1`=全丢）。**修正前实现的是保留率**（实际置零 80%），
  该口径的全部结果已作废并归档 `runs/prior_dropout80/`，见 `decisions.md` §26。
- **划分**：train 362 / val 45 / test 46（每 seed，`split_seed == seed`）；主种子 **seed0**（用途定位见 `decisions.md` §12）；训练种子与划分种子同名（`decisions.md` §16）。
- **标签序**（固定）：`access_control, arithmetic, dos, front_running, reentrancy, time_manipulation, uncheck`（reentrancy 下标 4）。
- **训练集逐类正样本** `train_pos`：seed0 `[11,10,4,2,21,2,35]`；seed1 `[11,10,4,2,19,3,35]`；seed2 `[11,10,4,2,21,3,35]`（全 7 类均含正样本，无 skipped class）。
- **口径**：主指标 **micro-F1（标签对级）**；macro-F1 为参考；阈值只在验证集搜索（0.20–0.80 步长 0.05，目标 val micro-F1，tie 取小）；测试集双报告（固定 0.5 + 验证集阈值）；support≤2 的类仅描述性呈现（`decisions.md` §13）。

**结论**

1. **🔴 已同配对 n=9 复核（2026-09-17，重训后）——focal 的"优势"不成立，结论回到「维持 bce」**：
   - `micro@0.5` **+0.0242（t=+1.02，不显著）**；`micro@val_thr` **+0.0210（t=+0.84，不显著）**；
     **`mAP` −0.0008（t=−0.05，零效应）**。
   - 逐种子方向也不一致（seed1 明显更好、seed0/seed2 更差，见 §1.10-b）⇒ **不是被噪声掩盖的真效应，是真没有效应**。
   - ⚠ 本条**推翻**了 `decisions.md` §27.3 的裁定（"focal 是真实的小幅改进"）与旧表的 `+0.0072（t=+2.80 显著）`：
     那些数字建立在**坏指标选出的退化权重**上。**§27.4 原本的建议 A（维持 bce）反而是对的**，只是当时的理由错了。
   → **建议维持 bce**（`decisions.md` §27.4 方案 A 恢复生效）；focal 不再作为"改进线索"写入讨论。
2. **ASL 固定 0.5 崩溃是机制性的、且比旧口径更明确**：`@0.5 = 0.2185 ± 0.0393`（−0.2729，**t=−11.29**），
   精确匹配率塌到 **0.043**（几乎全判正）；而 `@val_thr` 0.5023、mAP 0.4285 最高。
   其负样本调制 `(p−0.05)^4` 把负样本梯度压到近零、模型不再被推低 → 概率整体膨胀 → recall≈1、FP 爆炸。
   **验证集阈值（升至 0.70–0.75）能把它兜回来**，这是"固定 0.5"与"验证阈值"两套口径在此分歧最大的原因。
3. **但 ASL 的 mAP 优势在正确指标下不再显著**：旧表 **+0.0915（t=+3.31 ★）** → 新表 **+0.0239（t=+1.05）**。
   即"概率膨胀对排序指标有利"这一机制**方向仍在、幅度不足以显著**。不能据此称 ASL 是改进。
4. **有支撑的类响应损失形状，但幅度小于旧口径，且不一致**：验证阈值下 `uncheck`（test_pos=7）
   0.499 → focal 0.544 / **ASL 0.650**；`reentrancy`（test_pos=5）0.618 → focal **0.650** / ASL 0.564；
   而 `arithmetic`（test_pos=2）0.489 → focal **0.333** / ASL 0.467（focal 反而变差）。
   **`front_running` 在三种损失下恒为 0**（test_pos=1，oracle 上限 0.105）；`time_manipulation` 仅 ASL 得 0.125（±0.114，噪声级）。
   → **罕见类的瓶颈仍是 support，与损失形状无关**；有支撑类对损失形状的响应**没有一致方向**。
5. **与 §1.8/§1.9 合成一条主线（结论较旧版更强）**：四次干预（放开 `pos_weight`、温度缩放、per-class 阈值、focal/ASL）
   在**正确指标下全部未能改善主指标**——放开截断在**两个工作点上显著变差**、ASL 显著破坏 `@0.5`、
   focal 与温度缩放无显著效应。**唯一稳健的结论是"概率尺度类干预不是杠杆"。**
   下一阶段的真实杠杆是**数据侧**（阶段 G DIVE/SolidiFI 补稀有类）与**特征/结构侧**（阶段 F 消融），
   而不是继续调概率尺度与损失形状。

### 6.7 必须随表披露的混淆项

1. **aug 的 `.sol` 是去注释版**（保留空行以保行号）→ 图结构与 M1/M3 结构通道不受影响，但 `_cb.pt` 的
   CodeBERT 输入文本口径与主库**不同**，故 aug 与主库的绝对数字**不是纯语料差异的度量**。
2. **aug 的 M3 在 GPU 上构建，主库在 CPU 上构建**：GPU/CPU 同一文本的数值差 max|Δ|=5.6e-05
   （相对 3.5e-06，float32 累加顺序），远低于任何有意义阈值；两份 `_cb.pt` 不共享、无交互。
3. **aug 是单标签数据集**（每条非零恰一类，多标签仅 2 个），**勿套用主库的多标签叙事**；
   "多类共存"的实证主张仍只在 DIVE 外部测试上提。
4. **C1 覆盖约束在 aug 上算术不可行**（正样本率 79.7% > 66.7%），已按 §22 关闭 C1、保留 C2；
   该语料每类 val/test support ≥8，C1 的目的（评估可靠性）由数据本身满足。
5. **aug 显著比主库"易"**（micro-F1 **0.9901 vs 0.7110**，新正典 2026-09-20；冻结口径下曾是 0.9347 vs 0.4256）：
   其正样本为函数级注入、判别信号强；该语料的价值是**提供正样本充足的基准**，
   **不能**解读为"方法在主库问题上已达 0.99"。
   > ✅ 已复核（2026-09-20）：本句的比较量级已随新正典收窄（**0.9901 vs 0.7110**），
